# Trawl documentation

The [trawl.cloud](https://trawl.cloud) documentation site: ADRs, the operations
runbook, and the evidence-handling policy. Built with
[Astro](https://astro.build) + [Starlight](https://starlight.astro.build),
published to Cloudflare Workers as a static-assets Worker.

## Layout

```
src/content/docs/
├── adr/            Architecture decision records (autogenerated sidebar)
├── operations/     Runbooks — the on-call documents
├── security/       Evidence handling and security policy
└── index.mdx       Landing page (splash template)
src/styles/         Brand accent ramp
src/assets/         Hero illustration
public/             Favicons and other static files served as-is
```

Every file under `src/content/docs/` becomes a route from its path. The ADR,
Operations, and Security sidebar groups autogenerate from their directories, so
a new page appears in the nav without touching `astro.config.mjs`.

## Commands

| Command           | Action                                                  |
| :---------------- | :------------------------------------------------------ |
| `npm install`     | Install dependencies                                    |
| `npm run dev`     | Dev server at `localhost:4321`                           |
| `npm run check`   | `astro check` — content schema, types, internal links   |
| `npm run build`   | Production build to `./dist/`                            |
| `npm run preview` | Serve the built site locally                             |
| `npm run deploy`  | Build and `wrangler deploy` (needs Cloudflare auth)     |

## CI and deployment

`npm run check` and `npm run build` both run in the `docs` job of
`.github/workflows/ci.yml` on every pull request, alongside a
`wrangler deploy --dry-run` that validates `wrangler.jsonc`. A push to `main`
touching `docs/**` triggers `.github/workflows/docs.yml`, which rebuilds and
deploys.

Deployment needs two repository secrets:

- `CLOUDFLARE_API_TOKEN` — scoped to Workers Scripts: Edit
- `CLOUDFLARE_ACCOUNT_ID`

The `site` option in `astro.config.mjs` sets canonical URLs and the sitemap. It
must match the domain the site is actually served from.

## Domain

The site is served from the apex, `trawl.cloud`, attached as a Custom Domain in
`wrangler.jsonc` — Cloudflare manages the DNS record and the certificate.

`www.trawl.cloud` should redirect to the apex. That is a zone-level rule rather
than Worker config, so it is applied once in the dashboard and not from this
repository:

> **Rules → Redirect Rules → Create rule**
> - **When**: `Hostname` `equals` `www.trawl.cloud`
> - **Then**: Dynamic redirect, `301` (permanent)
> - **Expression**: `concat("https://trawl.cloud", http.request.uri.path)`
> - Preserve query string: **on**

A 301 rather than a 302 because the apex is canonical and this is not expected
to change. Serving the same content on both hostnames instead would work, but
splits a single site across two origins for no benefit.

## Creating the CI token

`CLOUDFLARE_API_TOKEN` cannot be minted from an OAuth session, so it is created
once in the dashboard: **My Profile → API Tokens → Create Token → Custom
token**, with `Account` / `Workers Scripts` / `Edit`, scoped to this account
only. Nothing else — a deploy token that can read zones or edit DNS is a
larger secret than this job needs.
